Why these answers are exact

Every TDS question is a pure function of your email address. The exam builds each student's variant with a seeded generator — questionId # your-email # version — and that generator ships to the browser as an ordinary JavaScript module. This page loads that module and calls it. Nothing here re-implements a question, so there is nothing to drift out of date and nothing to guess: the values you see are the values the grader was built from.

For the search-operator question the answer is a query rather than a value, so it is searched for and then checked with the exam's own matcher — the result is only shown when it returns the target set exactly, with no extras and no misses, inside the token budget.

What it cannot do, honestly

The five policy gates are graded by the exam calling your live endpoint with hidden payloads. Those ten marks cannot be derived from an email by this tool or any other — they need a service that actually behaves correctly. Anything claiming otherwise is guessing.

Street View sits in between. Its image is chosen server-side, so nothing can be derived — but a vision model can name the landmark, and the question is graded on the city, not the landmark. Open question six for that; it is the one place a token is used, it goes straight from your browser to aipipe.org, and it is never stored.

So: four marks exact, two marks assisted, ten marks that need your own running service.
